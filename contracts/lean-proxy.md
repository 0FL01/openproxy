# Lean proxy contract

This is the frozen C00 boundary for the [lean plan](../docs/CHECKPOINTS.json). The machine-checkable inventory is [`lean-proxy.json`](lean-proxy.json); implementation registries remain authoritative for exact runtime dispatch.

## Ownership

| Concern | Sole owner |
|---|---|
| Conversation history, compaction, tool execution, semantic repair, and temporal generation retries | OpenCode or the calling harness |
| Private credentials/OAuth, configured account/model routing, required protocol mapping, HTTP transport reuse, and resource/security limits | OpenProxy |

OpenProxy must not truncate, restore, or semantically reinterpret client prompt/history/tools. It may replace the routed model identifier, add provider-required wire fields and headers, translate protocols, refresh credentials, and try an eligible configured account within one bounded request-scoped attempt budget.

## Supported surface

The route and format-pair allowlists are in `lean-proxy.json`. Their source registries are:

- routes: `src/server/api/mod.rs`;
- provider target formats and translation pairs: `src/core/translator/registry.rs`;
- provider-specific executor dispatch: `src/server/api/chat.rs::forward_with_provider_fallback`;
- model metadata/discovery: `src/server/api/v1_models.rs::build_models_list`.

Same-format transport may be minimal, but byte-for-byte identity is not promised when model routing or a documented adapter requirement changes the body. Native streaming must not become collection merely to share an implementation.

C09 makes that minimal path a protocol decision: `source_format == target_format`
after dynamic model metadata is applied. Recognized, unknown, and absent client
identities therefore receive the same request semantics. Client detection remains
only for genuine transport preferences such as DeepSeek TUI streaming. OpenProxy
still replaces the routed model and applies documented native adapter wire guards,
but it does not autonomously re-anchor cache markers. Native Messages input reaches
the planner unchanged; incompatible protocol pairs use the registered translator.

## Product and security invariants

The following chain is one contract and must remain consistent:

`ProviderDetailPageClient/useAvailableModels` → `buildAvailableModels` → `ModelSelectModal` → OpenCode tool configuration → `/v1/models` → `plugins/openproxy-models.js`.

It preserves user custom/enabled/disabled models and canonical `opencode.source`. It also preserves TLS, SSRF protection tied to the actual connection, encrypted credentials, API/dashboard authentication, bounded audit behavior, provider-native cache fields/usage, required continuation state, and HTTP connection pooling.

The `openproxy.v1.*` namespace remains additive-only. Retired behavior is not assigned a new meaning under an existing field.

## Legacy data and migration

Persisted types intentionally preserve unknown fields through `extra` and `providerSpecificData`. Lean migrations therefore obey these rules:

1. Do not delete legacy values while loading or normalizing a database. Deprecated values remain exportable and round-trip unchanged unless a later checkpoint declares a separate data migration.
2. Stop consulting retired policy fields on the hot path, but do not silently reinterpret them. A rollback may re-enable the old reader without reconstructing user data.
3. In-memory replay/cache state is deleted, not moved to SQLite or replaced by another TTL/LRU cache.
4. Diagnostic lock/cooldown/health fields never suppress routing. Explicit user actions may clear them; success does not perform synchronous configuration housekeeping.
5. Configuration/credentials remain durable. Metadata logging may be lossy only in an explicitly selected lean mode with bounded event/byte queues and visible drop accounting.

| DefaultExecutor request serialization | C27 applies all DefaultExecutor body transforms once, writes JSON through a checked 64 MiB bounded serializer, and keeps one request-scoped `Bytes` representation. | Executor response request-body lifetime | C28 removes full transformed request JSON from every executor response/result type, constructor, debug implementation, server wrapper, and `PreparedUpstreamBody`. The sole former reader, CLI `route --json`, recomputes the same `DefaultExecutor` transform locally after a successful send instead of extending the server response API. No `Arc<Value>`, cache, unsafe ownership, schema, route, translator, tool, usage, fallback, or transport change was introduced. A 4 MiB held-EOF SSE test proves tool-call and usage frames arrive before EOF and downstream cancellation drops the upstream body without another attempt. |
| Collected upstream response bodies | C29 replaces generation-path whole-body reads with one checked Reqwest/Hyper reader. Successful JSON and protocol-adapter collections default to 64 MiB (`OPENPROXY_MAX_UPSTREAM_JSON_BYTES`); diagnostic/error bodies default to 1 MiB (`OPENPROXY_MAX_UPSTREAM_DIAGNOSTIC_BYTES`). Positive integer environment overrides provide rollback/tuning without disabling enforcement. Every yielded byte, including Reqwest-decompressed bytes, is checked with `checked_add` before reserve/growth; identity-encoded `Content-Length` can reject a declared oversize body early, while an encoded wire length is never mistaken for a decoded length. Oversized or partially failed success reads return 502 before commitment and never expose partial JSON. Diagnostics retain the upstream status and `Retry-After`, fit an explicit truncation or transport-incomplete marker inside their budget, and never become successful payloads. Dashboard collection, forced SSE-to-JSON, non-stream JSON, the non-SSE stream guard, and upstream error extraction use these distinct policies. CommandCode, Cursor protobuf, Windsurf gRPC-web, Trae, Zed, and Grok Web protocol collectors use the same strict primitive. Existing native chat SSE Reqwest/Hyper loops, Codex's bounded first-event preflight, post-commit behavior, and C13's attempt budget remain streaming and unchanged. |
| Required image inlining | C30A fetches remote images only when translation targets an adapter already declared to require inline image bytes; native OpenAI and Claude passthrough retain URLs and perform zero image fetches. Codex retains only its pre-existing remote `image_url` part handling, now once at the request boundary rather than once per account attempt; existing `data:` URLs and `detail` survive. The image reader defaults to 10 MiB per decoded image, 32 MiB aggregate decoded bytes, 48 MiB aggregate encoded data-URL bytes, and a final serialized request estimate/exact check capped at C27's 64 MiB prepared-body ceiling. Positive byte overrides are `OPENPROXY_MAX_IMAGE_DECODED_BYTES`, `OPENPROXY_MAX_IMAGE_AGGREGATE_DECODED_BYTES`, `OPENPROXY_MAX_IMAGE_AGGREGATE_ENCODED_BYTES`, and `OPENPROXY_MAX_IMAGE_REQUEST_BYTES`; invalid/zero values retain defaults and the final limit cannot exceed 64 MiB. Only identity `Content-Length` rejects early; actual Reqwest-yielded/decompressed chunks use checked arithmetic and fallible reserve before growth. Base64 length is checked before allocation and data URLs are encoded directly into one pre-sized string; Claude receives its native `{type,media_type,data}` source without an intermediate encoded copy. Size, aggregate, capacity, and final-budget failures return 413; URL, DNS/SSRF, transport/status, MIME/magic, and malformed-attachment failures return 502 before generation. Image order and bytes remain request-owned. No cache, LRU, timer, text replacement, or URL-on-failure fallback was added. C30B still owns the existing `_pinned_ip` connect-binding gap; C30A does not weaken scheme, DNS/private-IP, redirect, TLS, MIME, or magic checks. |
| Required image SSRF connect binding | C30B resolves every non-literal image hostname once per redirect hop, removes private/reserved IPv4 and IPv6 candidates, and supplies every remaining address to Reqwest's resolver override for the actual socket connect. The original URL hostname remains unchanged, so HTTP `Host`, TLS SNI, and certificate-name verification still use it. A connect failure cannot fall back to an unvalidated DNS lookup. Literal addresses are validated directly; loopback, private, link-local, unique-local, multicast, unspecified, shared-space, reserved, and IPv4-mapped private addresses are blocked. System proxies are disabled for this direct security-sensitive fetch because they could independently resolve the hostname. Redirects use a newly validated, pinned client and retain the existing hop bound, C30A byte/MIME/magic checks, and cancellation. No normal pooled client policy is relaxed and no pinned client is cached across requests. Deterministic resolver/connect/TLS tests verify the code risk; they do not claim a live exploitation demonstration. |
